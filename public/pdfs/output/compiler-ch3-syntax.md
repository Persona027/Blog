1 语法分析简介
语法分析器在编译器中的位置
语法分析器（Syntax Analyzer / Parser）位于编译器的前端，处于词法分析器之后、语义分析器之
前。词法分析器将源代码转换为记号流（TokenStream），语法分析器接收记号流并输出语法树（Syntax
Tree），语义分析器再基于语法树进行后续处理。[p.5-6]
语法分析器的任务
给定语言语法规则和记号流，语法分析器的核心任务是回答：该记号流是否可以由给定文法产生？
如果可以，则构造语法树；如果不可以，则报告语法错误。[p.6, p.33]
形式上：给定文法 G 和记号流构成的句子 α，问是否存在从开始符号 S 到 α 的推导。[p.32]
为什么不能用正则表达式？
正则表达式无法描述嵌套/递归结构。例如，对于可能带括号的算式，正则表达式无法记住前面是
否出现过左括号。因此需要表达能力更强的工具——上下文无关文法（CFG）。[p.13-14]

2 上下文无关文法
乔姆斯基文法体系
Noam Chomsky 将文法分为四个层次：[p.14]
1. 0-型文法（无限制文法）：α → β，α 至少含一个非终结符
2. 1-型文法（上下文有关文法）：γ Aγ → γ δγ ，要求 |α| ≤ |β|
1 2 1 2
3. 2-型文法（上下文无关文法）：A → δ，A ∈ V , δ ∈ (V ∪V ) ∗
N N T
4. 3-型文法（正规文法）：A → αB 或 A → α（右线性）
四个文法类逐渐增加限制，包含关系为：3-型 ⊂ 2-型 ⊂ 1-型 ⊂ 0-型。现今大多数高级程序设计语
言使用上下文无关文法描述语法已足够。[p.20]
上下文无关文法的形式化定义
一个上下文无关文法 G 是一个四元组 G = (T,N,P,S)：[p.26]
• T：终结符（Terminal）集合
• N：非终结符（Non-terminal）集合
• P：产生式规则集合，每条规则形式为 X → β β ...β ，其中 X ∈ N，β ∈ (T ∪N)
1 2 n i
• S：唯一的开始符号，S ∈ N
也可以记为 G = (V ,V ,S,P)，其中 V ∩V = ∅，S ∈ V 。产生式一般形式：A → α | β。[p.15]
N T N T N
2-型文法的扩充
允许产生式右部为空串：A → ε。即 δ ∈ (V ∪V ) ∗，而非强制 +。[p.19]
N T
BNF 范式
BNF（Backus-Naur Form）是上下文无关文法的一种实现表示方法。非终结符用尖括号表示，如
<E>，终结符直接写出，如 id。产生式用 ::= 表示。[p.29]

推导
给定文法 G，从开始符号 S 开始，用产生式右部替换左侧的非终结符，反复进行直到不出现非终
结符为止，最终的串称为句子。[p.30]
最左推导与最右推导
• 最左推导（Leftmost Derivation）：每次总是选择最左侧的非终结符进行替换。[p.31]
• 最右推导（Rightmost Derivation）：每次总是选择最右侧的非终结符进行替换。最右推导是自底
向上 LR 分析的基础。[p.31]
句型、句子、语言
∗
• 句型：设 S 是文法 G 的开始符号，若 S ⇒ u，则 u 为句型（u 可含非终结符）。[p.42]
• 句子：若 S ⇒ ∗ u 且 u ∈ V ∗，则 u 为句子。[p.42]
T
• 语言：L(G) = {u | S ⇒ ∗ u 且u ∈ V ∗}，即文法所有句子的集合。[p.42]
T
直接推导
若存在规则 A → β，且 γ,δ ∈ (V ∪V ) ∗，则有：γAδ ⇒ γβδ，称为直接推导。[p.44]
N T
文法等价
若 L(G ) = L(G )，则称文法 G 和 G 等价。[p.47]

3 语法树与二义性
推导与语法树的对应
推导可以表达成树状结构——语法树。不论推导所用的顺序（最左、最右或其他），都可以表示成
语法树。[p.39-40]
• 树中的每个内部节点代表非终结符
• 每个叶子节点代表终结符
• 每一步推导代表如何从父节点生成它的直接孩子节点
语法树的含义取决于树的后序遍历。[p.41]

4 自顶向下分析
自顶向下分析的算法思想
从文法的开始符号出发，尝试选择产生式推导出某个句子 t，比较 t 和要分析的句子 s。若 t = s
则接受，否则回溯尝试其他产生式。[p.56]
基本算法需要回溯（Backtracking），效率低。实际编译器需要线性时间的算法，于是引出了递归
下降分析算法和 LL(1) 分析算法。[p.60]
4.1 递归下降分析
基本思想
递归下降分析也称为预测分析（Predictive Parsing）。[p.63]
• 每个非终结符构造一个分析函数
• 对产生式右部的每个非终结符调用其分析函数
• ” 吃掉” 产生式右部的每个终结符
• ”|” 转换为”else-if” 分支，用前看符号指导分支选择
[p.66]
递归下降分析的特点：
• 分析高效（线性时间）
• 容易手工编码实现
• 错误定位和诊断信息准确
• 被 GCC 4.0、LLVM 等众多编译器采用
[p.63]

4.3 LL(1) 分析冲突处理
LL(1) 文法的判定条件
文法 G 为 LL(1) 文法当且仅当 G 中的任意两条产生式 A → α | β 满足：[p.113]
1. 当 α 与 β 都不能推导出 ε，则 FIRST(α) 与 FIRST(β) 不相交
2. 当 α 或 β 能推导出 ε：
• 若 α 能推导出 ε，则 FIRST(β) 与 FOLLOW(A) 不相交
• 若 β 能推导出 ε，则 FIRST(α) 与 FOLLOW(A) 不相交
冲突消除策略
策略1——FIRST相交：提取左公因子。[p.116]将A → γα | γβ 改写为A → γA ′ ,A ′ → α | β 。
1 2 1 2
策略 2——都含 ε：删除某一产生式中的 ε。[p.117]
策略 3——ε 导致 FIRST 与 FOLLOW 相交：展开产生式，消除左递归或提取左公因子。[p.118-
119]
• Case 1: 提取左公因子（展开 ε 候选式）
• Case 2: 消除左递归
• Case 3: 某些情况下可能失败（FIRST 与 FOLLOW 永远相交）[p.120]
无回溯文法的不可判定性
并非所有的 CFG 都有对应的无回溯文法。对于任意的 CFG，其是否存在无回溯文法是不可判定
的。[p.121]

点记号与 LR(0) 项目
为了方便标记语法分析器已经读入了多少输入，引入点记号”•”。一个产生式加入一个圆点，成为
一个 LR(0) 项目（Item）。[p.130]
例如：E → •E +T 表示尚未读入任何 E 的右部符号；
E → E •+T 表示已经读入 E，还期待读入 +T；
E → E +T• 表示已读入所有右部符号，可以归约。
移进-归约的过程
两个基本操作：[p.133]
• 移进（Shift）：将一个输入记号压入栈顶
• 归约（Reduce）：栈顶上的 n 个记号匹配某产生式右部时，将其弹出并压入该产生式左部
核心问题：如何确定移进和归约的时机？

• ACTION 表：以状态为行，终结符（包括结束符 $）为列，值为：
– s ：移进当前记号，转移到状态 n
n
– r ：用第 n 条产生式归约
n
– accept：接受
– 空白：出错

n

3. 根据当前状态栈栈顶状态，查询 GOTO 表，转移状态

5.1 LR(0) 分析算法
LR(0) 项目集规范族与 DFA 构造
LR(0) 分析表通过构造 DFA 来生成。DFA 的状态是项目集合（项集），DFA 的边是文法符号。
[p.145]
拓广文法（Augmented Grammar）：[p.152] 引入新的开始符号 S ′ 和产生式 S ′ → S$（或
S ′ → E），确保分析成功的唯一方式是使用 S ′ 产生式归约。
closure(I) 函数——求闭包：[p.154-156]
1. I 中的每个项目均加入 closure(I)
2. 如果 A → α•Bβ 在 closure(I) 中，且 B → γ 是产生式，且 B → •γ 不在 closure(I) 中，则加入
3. 重复步骤 2 直到不再增加
goto(I,X) 函数：[p.157] I ′ = goto(I,X) = closure({A → αX •β | A → α•Xβ ∈ I})
DFA 构造算法：[p.149-150]
初始项集 I0 = closure({[S' -> .S$]})
状态集合 states = {I0}
while 存在未处理的状态I:
for each 文法符号X:
J = goto(I, X)
if J非空且J不在states中:
states添加J
添加边 I --X--> J
LR(0) 分析表生成规则
对每个 DFA 状态（项集）：[p.148, p.169, p.173]
• 若项集中包含 A → α•aβ，且有状态 j 通过终结符 a 可达，则 ACTION[i][a] = s （移进）
j
• 若项集中包含 A → α•（点在末尾），则对所有终结符 ACTION[i][a] = r （用产生式 n 归约）
n
• 若项集中包含 S ′ → S •$（开始产生式完成），则 ACTION[i][$] = accept
• 若有通过非终结符 A 转移到状态 j 的边，则 GOTO[i][A] = j
LR(0) 的缺点
LR(0) 对于归约项直接对所有输入记号进行归约，导致两个问题：[p.179-184]
1. 延迟错误发现时机：在不该归约时归约，导致错误在后续步骤才被发现
2. 移进-归约冲突：某个状态同时有移进项和归约项，表中同一单元格出现多项
内在原因：LR(0) 项目只标识了” 需要归约”，没有标识” 何时归约”。因此对所有输入记号都进行归约。
[p.184]

• 有可能减少需要归约的情况
• 有可能去除移进-归约冲突
缺点：仍然有冲突出现的可能。因为 FOLLOW 集判断” 遇到产生式后面可能跟的所有输入都归
约”，这个条件不够精确。[p.189, p.193]
典型例子：S → L = R | R, L → ∗R | id, R → L，在状态 3（S → L• = R 和 R → L• 共存）中，
FOLLOW(R) = {=,$}，但对 = 做 R → L 的归约是不正确的，因为此时的上下文是期望看到 = 来匹
配 S → L = R。[p.190-193]
5.3 LR(1) 分析算法
LR(1) 项目的定义
LR(1) 项目定义为 [X → α•β,a]，其中 a 是前看符号（Lookahead）。含义：[p.194, p.196]
• 已读入 α
• 剩余的输入能够匹配 βa；当 β = ε 时，仅当下一输入符号为 a 时才能用该产生式归约
与 LR(0) 的关系：
• LR(0)：项目为 [X → α•β]
• SLR：遇到 FOLLOW(X) 中的所有输入都归约
• LR(1)：在遇到推导过程中该产生式后面可能跟的输入才归约，更精确
[p.194]
前看符号的计算（归纳法）
利用推导过程来传播前看符号：[p.195]
若推导链为：S ′ ⇒∗ αYβ$ ⇒ αγβ$，其中：
• [S ′ → S•,a] 中 a = $
• [S → αYβ•,b] 中 b = $
• [Y → γ•,c] 中 c = β（若 β ̸= ε）；或 c = $（若 β = ε）；或 c = FIRST_S(βb)！

同心 LR(1) 项目集：核心（第一分量集合）相同，仅搜索符不同的项目集。例如 [B → •bB,$]
与 [B → •bB,b/a] 是核心相同的。[p.202]
LALR 的实现
1. 先构造 LR(1) 的各个项目集
2. 合并所有同心项目集，前看符号取并集
3. 修改 ACTION 表和 GOTO 表以反映合并效果

二义性文法的 LR 处理

1. α,β 都不能 ⇒∗ ε：FIRST(α)∩ FIRST(β) = ∅

LR/SLR/LR(1)/LALR 的冲突判定
• 移进-归约冲突：某状态同时有移进项和归约项，且对同一输入分别需要移进和归约
• 归约-归约冲突：某状态有两个不同产生式的归约项（且对同一输入都可以归约）
• SLR 可以解决 LR(0) 的部分冲突，但不能解决所有
• LR(1) 可以解决 SLR 的冲突（通过精确前看符号）
