## 网络层概述与Internet架构

### 网络层在协议栈中的位置

- 网络层位于传输层之下、数据链路层之上 [p.3]
- Internet模型：应用层 → 传输层 → 网络层 → 网络接口层 [p.3]
- 网络层核心协议：IP（网际协议），配合ICMP、ARP、RARP及各种路由协议工作 [p.4]
- 网络层的地址是**IP地址**（32位），区别于传输层端口地址、网络接口层MAC地址 [p.5]

### 物理地址 (MAC地址) [p.6]

- MAC地址用于局域网内找到目标计算机 [p.6]
- IEEE 802标准：6字节（常用）或2字节 [p.6]
- 前3字节由IEEE分配给厂商（OUI），后3字节厂商自行分配 [p.6]
- 例如：00-00-C0-26-8C-00（CISCO） [p.6]

## IPv4地址

### IP地址基本概念 [p.8--10]

- 32位二进制数，每8位一组，点分十进制表示（0--255） [p.8]
- IP地址 = 网络号 + 主机号（两级结构） [p.9--10]
- 网络上每个接口分配一个全球唯一的32位标识符 [p.9]
- 网络号相同的一段连续IP地址空间称为"前缀"或"网络前缀" [p.9]

### IP地址分类 [p.11]

- A类：0.0.0.0 -- 127.255.255.255，前8位网络号，首位为0
- B类：128.0.0.0 -- 191.255.255.255，前16位网络号，前2位为10
- C类：192.0.0.0 -- 223.255.255.255，前24位网络号，前3位为110
- D类：224.0.0.0 -- 239.255.255.255，组播地址
- E类：240.0.0.0 -- 255.255.255.255，保留
- A/B/C类为单播地址 [p.11]

### 特殊IP地址 [p.12--13]

| 地址 | 含义 | 用途 |
| --- | --- | --- |
| 全0 (0.0.0.0) | 本网络本主机 | 启动时临时通信 |
| 网络号全0+主机号 | 本网络中的某主机 | -- |
| 全1 (255.255.255.255) | 有限广播 | 本地广播，无需知道网络地址 |
| 网络号+全1主机号 | 定向广播 | 向指定网络广播 |
| 127.x.x.x | 本地回环 | 测试网卡及TCP/IP软件（通常127.0.0.1） |

### 私有地址 (Private Address) [p.14]

- 私有地址不分配给任何组织，不能在Internet上使用 [p.14]
- A类私有：10.0.0.0 -- 10.255.255.255
- B类私有：172.16.0.0 -- 172.31.255.255
- C类私有：192.168.0.0 -- 192.168.255.255

## 子网划分 (Subnetting)

### 基本概念 [p.15]

- 子网划分(subnetting)：在内部将一个网络块划分为多个子网，对外仍是一个网络 [p.15]
- 子网掩码(subnet mask)：32位二进制数，置1表示网络位，置0表示主机位 [p.15]
- 子网划分将两级IP地址（网络号+主机号）变为三级（网络号+子网号+主机号） [p.15]
- 子网划分的好处：减少IP浪费、网络组织灵活、便于维护管理 [p.15]

### 子网掩码表示法 [p.16--17]

- 无子网时：

- A类默认掩码：255.0.0.0 (/8)
- B类默认掩码：255.255.0.0 (/16)
- C类默认掩码：255.255.255.0 (/24)

- 有子网时：网络标识号置1 + 子网标识号置1 + 主机标识号置0 [p.17]
- 例如：A类IP有子网掩码255.240.0.0，B类255.255.240.0 [p.17]

### 子网判断方法 [p.18]

- TCP/IP内部进程识别方法：将IP地址与子网掩码做**逻辑与运算** [p.18]
- 对源IP和目的IP分别与子网掩码做与运算 [p.18]
- 结果一致 → 同一本地网络，直接传输 [p.18]
- 结果不一致 → 远程网络，发送给网关 [p.18]

### 子网划分例题 [p.19--26]

- 例题1 [p.19--22]：本机IP 128.127.126.101，目的IP 128.127.2.32，4位子网标识号，判断本/远程。掩码为255.255.240.0，源与结果=128.127.112.0，目的与结果=128.127.0.0，不一致→送路由器
- 例题2 [p.23]：IP 195.201.33.117/255.255.255.224，主机位5位，可容纳$2^5-2=30$台主机
- 例题3 [p.24--26]：IP 195.201.33.77/255.255.255.224，网络地址195.201.33.64，广播地址195.201.33.95
- 关键公式：**可用主机数 = $2^{主机位数** - 2$}（减2是因为全0为网络地址，全1为广播地址）

## 无类域间路由选择 (CIDR)

### CIDR基本思想 [p.27--28]

- 分类IP的问题：A类地址过大、C类地址有时太小，浪费地址空间 [p.27]
- 解决方法：取消IP地址分类，使用CIDR [p.27]
- CIDR将32位IP地址分为网络前缀+主机号两部分，采用**斜线记法**：IP地址/前缀位数 [p.28]
- 例如：192.168.8.0/21 [p.29]
- 路由聚合(route aggregation)也称构成超网(supernet) [p.28]
- CIDR允许前缀重叠，数据包按**最长前缀匹配**方向发送 [p.28]

### CIDR路由聚合条件 [p.31]

- 条件1：待汇总地址的网络号拥有**相同的高位** [p.31]
- 条件2：待汇总的网络地址数目必须是**$2^n$**（如2、4、8、16个等） [p.31]
- 不满足条件可能导致**路由黑洞**（汇总后网络包含实际不存在的子网）[p.31]

### CIDR转发过程 [p.32]

- 分组到来，与子网掩码做与运算，找匹配项 [p.32]
- 如有多个匹配项，选掩码长度**最长**的那个 [p.32]

### 最长前缀匹配 (Longest Prefix Match) [p.37--38]

- CIDR可变长子网掩码及路由聚合，需要最长前缀匹配实现最精确匹配 [p.37]
- IP地址与IP前缀匹配时，总是选取子网掩码最长的匹配项 [p.37]
- 主要用于路由器转发表项匹配，也应用于ACL规则匹配 [p.37]
- 例题 [p.38]：路由表中多条匹配项（/9, /10, /8, /24, /0），目的IP 2.5.1.22 匹配 interface 3（2.2.3.0/24）、200.1.22.15 匹配 interface 2（2.128.0.0/9）、150.1.23.150 匹配 interface 5（0.0.0.0/0 默认路由）

## 地址解析协议 (ARP)

### ARP基本概念 [p.39--40]

- ARP (Address Resolution Protocol, RFC 826)：实现IP地址到MAC地址的动态转换 [p.39]
- RARP：实现MAC地址到IP地址的逆向转换 [p.39]
- 每台主机维护ARP表（ARP Cache），存放IP地址与MAC地址的映射 [p.40]
- ARP表存放在主机的**高速缓冲区**中，启动时为空 [p.40]
- ARP缓存映射项**几分钟后超时** [p.40]

### ARP工作过程 [p.41--44]

- 主机A要发送数据给主机B，已知B的IP地址，需获取B的MAC地址 [p.41,43]
- 若ARP表中有B的映射，直接从ARP表获取 [p.43]
- 若ARP表中无缓存，A在局域网内**广播ARP query**分组 [p.43]
- 局域网所有节点都可收到ARP query [p.43]
- B收到ARP query后，将自己的MAC地址**单播**发送给A [p.43--44]
- A在ARP表中缓存B的IP-MAC映射，超时时删除 [p.43]
- IP地址到物理地址的方法：表格法、直接映射、动态联编 [p.42]

### IP数据包转发流程 [p.41]

- 检查目的IP地址的网络号部分 [p.41]
- 若目的主机与源主机在同一IP网络 → 直接封装到链路层帧发送 [p.41]
- 若不在同一网络 → 发送给网关 [p.41]

## IPv4协议

### IPv4概述 [p.45]

- IPv4 (Internet Protocol version 4)：互联网的核心协议，使用最广泛的网际协议版本 [p.45]
- 无连接协议 [p.45]
- 两个基本功能：**寻址(addressing)**和**分片(fragmentation)** [p.45]
- 定义于RFC 791 [p.45]

### IPv4数据报格式 [p.46--47]

- 版本(Version)：4 bit，值为4 [p.46]
- 首部长度(IHL)：4 bit，表示IP首部长度，单位32bit [p.46]
- 区分服务：8 bit，一般情况不使用 [p.46]
- 总长度(Total Length)：16 bit，表示整个IP报文长度，最大$2^{16}-1=65535$字节 [p.46]
- 标识(Identification)：16 bit，IP软件通过计数器自动产生，用于分片后标识同一数据报 [p.46]
- 标志(Flags)：3 bit，目前只有两位有意义 [p.46]：

- MF (More Fragment)：置1表示后面还有分片，置0表示这是最后一个 [p.46]
- DF (Don't Fragment)：置1时不允许分片，置0时允许分片 [p.46]

- 片偏移(Fragment Offset)：13 bit，表示分片后该IP片在总IP片中的相对位置 [p.46]
- 生存时间(TTL)：8 bit，以跳数计量，每经过一个路由器减1 [p.47]
- 协议(Protocol)：8 bit，标识上层协议（TCP/UDP/ICMP等） [p.47]
- 首部校验和：16 bit，只对数据报首部进行校验，不包括数据部分 [p.47]
- 源地址：32 bit，发送端IP地址 [p.47]
- 目的地址：32 bit，目的端IP地址 [p.47]
- 选项(Options)：可扩充部分，可变长度 [p.47]
- 填充(Padding)：全0填充，补齐为4字节的整数倍 [p.47]
- IP数据报由**首部**和**数据**两部分组成，首部至少20字节 [p.46--47]

### IP数据报分片 (Fragmentation) [p.48--53]

- MTU (Maximum Transmission Unit)：每种硬件技术规定了一帧能携带的最大数据量 [p.48--49]
- 路径MTU (Path MTU)：整体传输路径上各链路MTU的最小值 [p.48]
- 分片策略 [p.48]：

- 允许途中分片：根据下一跳链路MTU实施分片
- 不允许途中分片：发出的数据报长度须小于路径MTU（路径MTU发现机制）

- 重组策略 [p.48]：互联网采用**目的端重组**（途中重组实施难度太大）
- 重组所需信息 [p.48]：原始数据报编号（标识）、分片偏移量（片偏移）、是否收集所有分片（MF标志）
- IPv4分组在传输途中可以**多次分片**：源端系统、中间路由器 [p.53]
- IPv4分片只在**目的端**系统进行重组 [p.51,53]
- 只有最终目的主机才会对段进行重组 [p.51]
- 重组(reassembly)：在所有段的基础上重新产生原数据报的过程 [p.51]

### IP分片关键字段 [p.50,53]

- 标识(ID)：标识同一数据报的所有分片
- MF=0：无后续分段（最后一个分片）；MF=1：有后续分段
- DF=0：可以分段；DF=1：不允许分段
- OS (片偏移)：起始偏移量，以8字节为单位
- TL：数据长度
- 分片、重组的字段在基本IP头部：标识、标志、片偏移 [p.53]

### IP协议功能及报头字段总结 [p.54]

- 多跳寻路：目的IP地址 [p.54]
- 发送端身份：源IP地址 [p.54]
- 上层协议处理：协议字段 [p.54]
- 大数据报MTU问题：标识、标志、片偏移（分片机制） [p.54]
- 防止循环转发：TTL生存时间 [p.54]
- 报头错误校验：首部校验和 [p.54]

## NAT (网络地址转换)

### NAT基本概念 [p.55--56]

- NAT (Network Address Translation)：解决IPv4地址不足的问题 [p.55]
- 将私有地址转换为公有IP地址 [p.55]
- NAT功能通常集成到路由器、防火墙或单独NAT设备中 [p.57]
- NAT维护一个**状态表**，用来把内部地址映射到合法地址上 [p.57]

### NAT的三种用法 [p.57]

- 一对一：一个公有地址对应一个私有地址 [p.57]
- 几个公有地址对应几个私有地址 [p.57]
- **一个公有地址对应一大群私有地址**（端口NAT/PAT，最常见） [p.57]

### NAT类型 [p.58--59]

- **静态NAT**：内部本地地址与合法地址一对一转换，需指定对应关系。适用于对外提供服务的服务器（如Email、FTP服务器） [p.58]
- **动态NAT**：从合法地址池中动态选择一个未使用的地址进行转换 [p.59]
- **端口NAT (PAT)**：将内部TCP/IP映射到外部注册IP地址的**多个端口**上 [p.59]

### NAT表项管理 [p.61]

- NAT根据不同的IP上层协议进行NAT表项管理：TCP、UDP、ICMP [p.61]
- 传输层TCP/UDP拥有16-bit端口号字段，一个WAN侧地址可支持**60,000个并行连接** [p.61]

### NAT的优势与问题 [p.61]

- 优势：节省合法地址，减少地址冲突，灵活连接Internet，保护局域网私密性 [p.61]
- 问题/缺点 [p.61]：

- 违反了IP的结构模型（路由器处理传输层协议）
- 违反了端到端的原则
- 违反了最基本的协议分层规则
- 不能处理IP报头加密
- 新型网络应用设计者必须考虑NAT场景（如P2P应用程序）


## DHCP (动态主机配置协议)

### IP地址获取方式 [p.62]

- 公有IP地址要求全球唯一，由ICANN向ISP分配，ISP逐级分配 [p.62]
- **静态设定**：申请固定IP地址，手工设定（如路由器、服务器） [p.62]
- **动态获取**：使用DHCP协议，主机加入IP网络时从DHCP服务器动态获取IP地址 [p.62]

### DHCP基本概念 [p.63]

- DHCP (Dynamic Host Configuration Protocol)：动态主机配置协议 [p.63]
- 工作模式：客户/服务器模式 (C/S) [p.63]
- 基于**UDP**工作 [p.63]
- 服务器运行在**67号端口**，客户端运行在**68号端口** [p.63]

### DHCP工作过程 (DORA) [p.64--67]

- **DHCP DISCOVER**（发现）：客户端从UDP端口68以**广播**形式发送，源地址全0，目的地址255.255.255.255。若无反馈等待1秒重新广播，共5次，延时加长 [p.64,66]
- **DHCP OFFER**（提供）：DHCP服务器从67端口**单播**发出提供报文，从未分配IP地址中选取一个分配给该主机 [p.64,66]
- **DHCP REQUEST**（请求）：客户端从多个DHCP服务器中选择一个，并以**广播**形式发送请求报文 [p.64,66]
- **DHCP ACK**（确认）：被选择的DHCP服务器**单播**发送确认报文，IP分配正式生效 [p.64,66]

### DHCP工作过程小结表 [p.67]

| 阶段 | 源MAC | 目标MAC | 源IP | 目标IP | 传输 |
| --- | --- | --- | --- | --- | --- |
| Discover | PC的MAC | 全FF | 0.0.0.0 | 255.255.255.255 | 广播 |
| Offer | DHCP服务器MAC | 客户端MAC | 服务器IP | 待分配IP | 单播 |
| Request | PC的MAC | 全FF | 0.0.0.0 | 255.255.255.255 | 广播 |
| Ack | DHCP服务器MAC | 客户端MAC | 服务器IP | 待分配IP | 单播 |

### DHCP返回信息 [p.65]
除IP地址外，DHCP服务器还返回：默认路由器IP地址、DNS服务器IP地址、网络掩码 [p.65]

## ICMP (Internet控制报文协议)

### ICMP基本概念 [p.69]

- ICMP (Internet Control Message Protocol)：允许主机或路由器报告差错情况和提供异常情况报告 [p.69]
- ICMP报文携带在IP数据报中，IP上层协议号为**1** [p.69]

### ICMP报文类型 [p.69--72]

- **差错报告报文** [p.69]：

- 类型3：终点不可达（网络不可达、主机不可达、端口不可达、协议不可达）[p.72]
- 类型5：改变路由 (Redirect)
- 类型11：时间超时（TTL过期）
- 类型12：参数问题（坏的IP首部）

- **查询报文** [p.69]：

- 类型8/0：回送请求/应答 (Echo Request/Reply) —— ping使用
- 类型13/14：时间戳请求/应答 (Timestamp)


### ICMP报文格式 [p.71]

- 前4个字节包含格式统一的三个字段：类型(Type)、代码(Code)、检验和 [p.71]
- 相邻后四个字节内容与ICMP的报文类型有关 [p.71]

### 差错报告报文数据字段 [p.73]

- ICMP差错报告报文的数据字段包含：收到的IP原始数据报的**IP首部+前8字节** [p.73]

### Ping和ICMP [p.74]

- PING (Packet InterNet Groper)：用来测试两个主机之间的**连通性** [p.74]
- PING使用ICMP回送请求(Echo Request, Type 8)与回送应答(Echo Reply, Type 0)报文 [p.74]
- 通过TTL值可判断对方主机操作系统类型 [p.74]：

- Windows NT/2000: TTL=128
- Windows 95/98: TTL=32
- UNIX: TTL=255
- Linux: TTL=64

- ping返回信息：连通性、往返时延(RTT)、单向转发跳数 [p.74]

### Traceroute和ICMP [p.75--76]

- Traceroute用于知道整个路径上路由器的地址 [p.75]
- 工作原理 [p.75]：

- 源向目的地发送一系列UDP段（使用不可能的端口号）
- 第一个TTL=1，第二个TTL=2，依次递增
- 当第n个数据报到第n个路由器时，路由器丢弃数据报并向源发送ICMP报文（类型11，编码0——TTL过期）
- 报文的源IP地址就是该路由器的IP地址

- 停止条件 [p.76]：

- UDP段最终到达目的主机，目的地返回ICMP"端口不可达"分组（类型3，编码3）
- 源收到该ICMP即停止

- Traceroute针对同一RTT值执行上述过程**3次** [p.76]

### ICMP Redirect示例 [p.77]

- 主机A向主机B发送数据报，经路由器R1 [p.77]
- R1判断R2是最佳下一跳，向R2转发后向A发送重定向报文 [p.77]
- 主机A根据重定向报文中的目标路由器IP地址更新自己的路由表 [p.77]

### ICMP时间戳与时钟同步 [p.78--80]

- 类型13：时间戳请求；类型14：时间戳应答 [p.78]
- 字段：初始时间戳($t_初始$)、接收时间戳($t_接收$)、发送时间戳($t_发送$) [p.78]
- 往返时间计算公式：$$
往返时间 = t_当前 - t_初始 - (t_发送 - t_接收) = t_接收 - t_初始 + t_当前 - t_发送
$$ [p.79]
- 假设传输请求和传输应答的时延相同，单程时延 = 往返时间 / 2 [p.79]
- 时间差计算：$$
时间差 = t_接收 - (t_初始 + 单程时延)
$$ [p.80]
- 例题 [p.80]：$t_初始=1000$, $t_接收=1055$, $t_发送=1057$, $t_当前=1030$
    $$
往返 = 1030-1000-(1057-1055) = 28 ms
$$
    $$
单程 = 28/2 = 14 ms
$$
    $$
时间差 = 1055 - (1000+14) = 41 ms
$$
    主机B的时钟比主机A快41ms

## Internet路由协议概述

### 自治系统 (AS) [p.82--85]

- Internet采用核心路由器体系结构，不同网络划分成不同的**自治系统(AS, Autonomous System)** [p.82]
- AS：由公司、大学或ISP等不同组织运营的独立网络，遵循共同的路由策略 [p.85]
- 内部网关协议 (IGP, Interior Gateway Protocol)：在自治系统内部执行路由功能 [p.85]

- 如RIP、OSPF、IS-IS [p.85,104]

- 外部网关协议 (EGP, Exterior Gateway Protocol)：在不同自治系统间进行路由 [p.85]

- 如BGP-4 [p.85,104]

- Internet整体架构：IGP处理域内路由，EGP处理域间路由 [p.84]

## OSPF (开放最短路径优先)

### OSPF概述 [p.86]

- OSPF (Open Shortest Path First)：1989年开发，采用**分布式链路状态算法** [p.86]
- 基本思想 [p.86]：

- 向本自治系统中所有路由器**洪泛**信息
- 发送的信息就是与本路由器相邻的所有路由器的**链路状态**
- 只有当链路状态发生变化时，路由器才用洪泛法发送此信息


### 链路状态与LSDB [p.87]

- "链路状态"：说明本路由器都和哪些路由器相邻，以及该链路的"度量(metric)" [p.87]
- OSPF度量值一般包括：费用、距离、时延、带宽等 [p.87]
- 由于各路由器之间频繁交换链路状态信息，所有路由器最终都能建立一个**链路状态数据库(LSDB)** [p.87]
- LSDB实际上是区域内的拓扑结构图，在区域内是一致的（LSDB同步） [p.87]

### OSPF五种报文 [p.88]

- **Hello报文**：最常用，用于发现和维护邻居关系 [p.88]
- **数据库描述(DD)报文**：描述自己的LSDB内容，包括每条LSA的Header头部 [p.88]
- **链路状态请求(LSR)报文**：请求缺少的LSA [p.88]
- **链路状态更新(LSU)报文**：向对方发送所需的LSA，内容是多条LSA的集合 [p.88]
- **链路状态确认(LSAck)报文**：对收到的LSU报文进行确认 [p.88]

### OSPF报文交互过程 [p.89--90]

- **发现邻居**：使用HELLO报文，检查参数，参数一致形成邻居关系 [p.89]
- 对于广播和NBMA类型网络（帧中继、ATM），选举**指定路由器(DR)**和**备份指定路由器(BDR)** [p.89]
- **数据库同步**：使用DD报文进行主从路由器选举和数据库摘要交互 [p.90]
- DD报文包含LSA的头部信息，用来描述LSDB的摘要 [p.90]
- 建立完全邻接关系：LSR请求所需LSA → LSU发送 → LSAck确认 [p.90]
- OSPF状态机：ExStart → Exchange → Loading → Full [p.90]

### OSPF区域概念 [p.92--93]

- OSPF引入"分层路由"概念，将网络分割成相互独立的部分——"区域(Area)" [p.92]
- "主干"的部分称为"主干区域"(Area 0) [p.92]
- 每个区域如同一个独立的网络，区域内路由器只保存该区域的链路状态 [p.92]
- 详细拓扑结构信息仅在区域内传递，区域间传递的是抽象的路由信息 [p.92]
- 非主干区域之间不允许直接发布区域间路由信息 [p.92]
- 一个区域内的路由器最好不超过**200个** [p.92]
- 划分区域可以缩小LSDB规模，减少网络流量 [p.92]
- 路由器角色 [p.93]：

- **内部路由器(IR)**：所有接口在同一区域
- **区域边界路由器(ABR)**：连接多个区域，至少一个接口在Area 0
- **自治系统边界路由器(ASBR)**：连接其他AS

- Area 0为主干区域，所有ABR都至少有一个接口属于Area 0 [p.93]

### OSPF报文格式要点 [p.94]

- 协议封装：运行于IP协议之上，协议号**89** [p.94]
- 路由器标识符：一个32位的值，唯一标识一个自治系统内的路由器 [p.94]
- 区域标识符：每个区域有一个32位标识符（用点分十进制表示），主干区域为**0.0.0.0** [p.94]

### OSPF特点总结 [p.96]

- 支持无类域间路由(CIDR) [p.96]
- 无路由自环 [p.96]
- 收敛速度快 [p.96]
- 使用IP组播收发协议数据 [p.96]
- 支持多条等值路由 [p.96]
- 支持协议报文的认证 [p.96]

## RIP (路由信息协议)

### RIP概述 [p.97]

- RIP (Routing Information Protocol)：基于**距离向量算法**的协议 [p.97]
- 使用**跳数**衡量到达目的网络的距离 [p.97]
- 一个好的路由通过的路由器数目少，即"距离短" [p.97]
- RIP允许一条路径最多包含**15个路由器**（16为不可达） [p.97]
- 基本思想 [p.97]：

- 仅和**相邻路由器**交换信息
- 路由器交换的内容是自己的**路由表**
- **周期性更新**：每**30秒**


### RIP工作过程 [p.98--100]

- 初始化时，每个路由器只知道自己的直连网络 [p.98]
- 周期性向邻居发送自己的完整路由表 [p.99]
- 收到邻居的路由表后，将跳数+1，与自己的路由表比较更新 [p.98--100]

### RIP报文格式 (V2) [p.101--102]

- 协议封装：**UDP**，端口**520** [p.101]
- 版本演进 [p.101]：

- V1：使用标准的IP地址，**不支持子网路由**
- V2：支持子网路由、身份验证、多播


### RIP防环机制 [p.103]

- **触发更新**：路由变化时立即通知邻居
- **毒性反转**：将不可达路由以跳数16通告回去
- **水平分割**：从某接口学到路由不再从该接口发回

### RIP特点与适用场合 [p.103]

- 优点：算法简单，易于实现 [p.103]
- 缺点：

- 收敛慢 [p.103]
- 需要交换的信息量较大 [p.103]

- 适用场合：**中小型网络** [p.103]

## BGP (边界网关协议)

### BGP基本概念 [p.104]

- BGP (Border Gateway Protocol)：当前Internet中唯一实际运行的自治域间路由协议 [p.104]
- 功能 [p.104]：

- eBGP：从相邻AS获得网络可达信息
- iBGP：将网络可达信息传播给AS内的路由器
- 基于网络可达信息和策略决定到其他网络的"最优"路由


### BGP四种分组 [p.105]

- **Open**：与另外一个BGP建立联系 [p.105]
- **Update**：更新路由 [p.105]
- **Keepalive**：保活分组，证实相邻路由器的存在 [p.105]
- **Notification**（通知分组）：发送检测到的查错 [p.105]

### BGP连接：eBGP与iBGP [p.106]

- eBGP连接：不同AS的BGP路由器之间的连接 [p.106]
- iBGP连接：同一AS内BGP路由器之间的连接 [p.106]
- 边界路由器同时运行eBGP和iBGP协议 [p.106]

### BGP会话与路径通告 [p.107--109]

- BGP会话：两个BGP路由器通过**TCP连接**交换BGP报文 [p.107]
- BGP是**路径向量协议**：通告到不同网络前缀的路径，即AS路径序列 [p.107]
- 路径通告示例 [p.108]：AS3的3a向AS2通告路径(AS3, X)，AS2的2c通过iBGP传播，2a通过eBGP向AS1通告路径(AS2, AS3, X)
- 路由器可能学到多条到目的网络的路径，由策略决定选择哪条 [p.109]

### BGP协议特点 [p.110]

- 交换路由信息的结点数量级是**自治系统数**的量级（远小于路由器数） [p.110]
- 每个自治系统边界路由器的数目是很少的 [p.110]
- 刚运行时交换整个BGP路由表，以后只在变化时更新有变化的部分 [p.110]
- BGP为每个AS提供 [p.110]：

- 从邻居AS获取网络可达信息 (eBGP)
- 传播可达信息给所有域内路由器 (iBGP)
- 根据"可达信息"和"策略"决定路由


## IPv6技术

### IPv6概述 [p.112]

- 开发历程：1993年IETF成立IPng工作组 → 1995年完成IPv6协议版本 → 1999年成为标准草案 [p.112]
- 2008年北京奥运会成功使用IPv6网络，中国成为全球较早商用IPv6的国家之一 [p.112]
- CNGI (中国下一代Internet示范工程) 已成为全球最大的示范性IPv6网络 [p.112]

### IPv6主要特征 [p.113]

- 新的协议格式 [p.113]
- 巨大的地址空间（128位） [p.113]
- 有效的分级寻址和路由结构 [p.113]
- 有状态和无状态的地址自动配置 [p.113]
- 内置的安全机制 [p.113]
- 更好地支持QoS服务 [p.113]

### IPv6地址表示 [p.114--115]

- 128位地址，用**冒号十六进制**表示法 [p.114]
- 按每16位划分为8个位段，每段转换为4位十六进制数 [p.114]
- 例如：21DA:0000:0000:0000:02AA:000F:FE08:9C5A [p.114]
- **零压缩法** [p.115]：

- 段内前导0可省略：0000→0, 02AA→2AA, 000F→F
- 连续的0段可使用**双冒号(::)**压缩（只能用一次）

- 简化后：21DA:0:0:0:2AA:F:FE08:9C5A → **21DA::2AA:F:FE08:9C5A** [p.115]

### IPv6分组结构 [p.116--118]

- IPv6基本报头比IPv4简化，固定40字节 [p.116--118]
- IPv6分片机制有较大变化（使用扩展头处理） [p.53]

### IPv4到IPv6过渡 [p.119--122]

- **双协议栈**：设备同时运行IPv4和IPv6协议栈 [p.119]
- **隧道技术**：通过IPv4隧道传输IPv6分组 [p.120]
- 隧道结构类型 [p.121--122]：

- 路由器-路由器隧道
- 主机-路由器隧道
- 主机-主机隧道 (6over4)


## 路由器工作原理

### 路由器概述 [p.124]

- 路由器是互联网最主要的网络设备，包含2个核心功能 [p.124]：

- **控制层**：运行各种路由协议(BGP/OSPF/RIP)，学习去往不同目的的转发路径 → 路由表 [p.124]
- **数据层**：根据路由表，将收到的IP分组转发到正确的下一跳链路 [p.124]


### 路由器控制层 [p.125--126]

- 路由器可同时运行多个路由协议，也可只使用静态路由和直连路由 [p.125]
- 路由管理：根据路由优先级，选择最佳路由，形成**核心路由表** [p.125]
- 控制层将核心路由表下发到数据层，形成**转发表(FIB)** [p.125]
- 路由优先级（数值越小优先级越高） [p.126]：


| 路由种类 | 路由优先级 |
| --- | --- |
| 直连路由 | 0 |
| 静态路由 | 1 |
| eBGP路由 | 20 |
| OSPF路由 | 110 |
| RIP路由 | 120 |
| iBGP路由 | 200 |


### 路由器数据层 [p.127--128]

- IP报文转发核心功能 [p.127]：

- 链路层解封装，IP头部校验
- 获取报文目的IP地址
- 基于最长前缀匹配规则查询转发表
- 查询失败 → 丢弃报文；查询成功 → 获取转发出接口和下一跳IP地址
- IP头部"TTL"字段值减1，重新计算IP头部"校验和"
- 重新进行链路层封装，发送报文

- 普通IP报文转发过程中，路由器不查看传输层及以上层协议的内容 [p.127]
- IP报文在路由器转发前后的变化 [p.127]：

- 链路层封装更新
- TTL减1
- 校验和更新

- 数据报在不同硬件单元的处理 [p.128]：

- 输入接口卡：链路层解封装 → 转发表查询
- 交换结构(Switching Fabric)：从输入接口卡发往输出接口卡
- 输出接口卡：排队处理 → 链路层封装 → 发送报文


### 路由器技术演变 [p.129--132]

- 第一代：单总线单CPU结构 [p.129]
- 第二代：多总线多CPU结构 [p.130]
- 第三代：交换结构的Gbps路由器 [p.131]
- 第四代：多级交换路由器，采用网络处理器(NP)，兼顾性能与可编程能力 [p.132,134]

## 第三层交换

### 基本概念 [p.133]

- 90年代中期提出"第三层交换"概念 [p.133]
- 将第三层成熟的路由技术与第二层高性能的硬件交换技术相结合 [p.133]
- 目的：快速转发、保证服务质量(QoS)、提高路由器性能 [p.133]
- 第三层交换机通过内部路由选择协议（如RIP或OSPF）创建和维护路由表 [p.133]
- 提供防火墙分组过滤等服务 [p.133]
- 功能由硬件实现，使用专用集成电路(ASIC)，而不是路由处理软件 [p.133]

## 核心考点速记

### 关键公式与计算

- **可用主机数**：$2^{主机位数} - 2$ [p.23]
- **网络地址**：IP地址 AND 子网掩码 [p.15,18]
- **广播地址**：网络地址中主机位全置1 [p.25]
- **CIDR聚合**：找最长公共前缀，要求网络数为$2^n$ [p.31]
- **最长前缀匹配**：多个路由表项匹配时选掩码最长的 [p.32,37]
- **片偏移**：以8字节为单位（13bit片偏移字段） [p.46]
- **ICMP往返时间**：$RTT = t_当前 - t_初始 - (t_发送 - t_接收)$ [p.79]
- **ICMP时间差**：$时间差 = t_接收 - (t_初始 + 单程时延)$ [p.80]

- TTL典型值：Windows=128, Linux=64, UNIX=255 [p.74]

- DHCP服务器端口：67；客户端端口：68 [p.63]
